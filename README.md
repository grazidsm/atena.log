## O projeto

A **Benigno Soluções** é a empresa de desenvolvimento simulada pelo grupo. O cliente desta
etapa é a **RH Soluções**, que procurou a empresa porque metas e satisfação dos colaboradores
eram acompanhadas separadamente — o gestor só percebia um problema quando ele já estava grande.

O levantamento de requisitos partiu desse pedido e resultou em **28 requisitos** (20 funcionais
e 8 não funcionais), priorizados em MoSCoW e rastreados até a fonte que os originou.

**Sistema análogo analisado:** Culture Amp.

---

## Processo de requisitos adotado

O processo da Benigno Soluções é centrado em requisitos: tudo o que o sistema precisa fazer é
descoberto, organizado e conferido com o cliente antes de virar código.

| # | Fase | Para que serve |
|---|---|---|
| 1 | **Elicitação** | Descobrir o que o cliente realmente precisa — questionário com entrevista, observação e alinhamento final |
| 2 | **Análise** | Organizar o que foi coletado — identificação dos requisitos, modelagem ER e priorização MoSCoW |
| 3 | **Especificação** | Descrever cada requisito sem dupla interpretação — histórias de usuário, critérios de aceitação e Planning Poker |
| 4 | **Gerenciamento** | Controlar mudanças — matriz de rastreabilidade bidirecional, controle de riscos e custos, verificação |
| 5 | **Prototipação contínua** | Validar telas com o cliente durante todo o projeto, não só no final |
| 6 | **Entrega final** | Entregar o sistema validado e mantê-lo funcionando |

Um erro de entendimento descoberto no começo custa uma conversa; descoberto depois da entrega,
custa reescrever parte do sistema. Por isso cada requisito é conferido com o cliente mais de uma vez.
